步骤 1: 确保你在主分支上
首先，确保你当前在主分支上（通常是 main 或 master）。你可以通过以下命令查看当前分支：

sh
git branch
如果当前不在主分支上，可以切换到主分支：

sh
git checkout main
或者

sh
git checkout master
步骤 2: 更新主分支
确保你的主分支是最新的。你可以通过以下命令拉取最新的更改：

sh
git pull origin main
或者

sh
git pull origin master
步骤 3: 创建新分支
创建一个新的分支来测试你的代码修改。你可以使用以下命令创建并切换到新分支：

sh
git checkout -b test-auto-reconnect
这里的 test-auto-reconnect 是新分支的名称，你可以根据需要更改。

步骤 4: 进行代码修改
在新分支上进行你的代码修改。例如，你可以在 client.cpp 文件中进行修改，以实现自动重连功能。

步骤 5: 提交修改
完成代码修改后，添加修改的文件到暂存区，并提交更改：

sh
git add client.cpp
git commit -m "Add auto-reconnect functionality in client"
步骤 6: 测试修改
在新分支上编译并运行你的客户端程序，确保自动重连功能按预期工作。

sh
g++ -o client client.cpp ../tool/tool.cpp ../tool/clitool.cpp ../tool/jsontool.cpp ../../chat/user/user.cpp ../../chat/user/userprofile.cpp -lws2_32 -lrpcrt4
./client
步骤 7: 推送新分支到远程仓库
如果你希望将新分支推送到远程仓库，可以使用以下命令：

sh
git push origin test-auto-reconnect

步骤
1. 切换到 multi 分支
首先，切换到目标分支 multi：

sh
git checkout multi
如果提示 multi 分支不存在，可能需要从远程拉取：

sh
git fetch origin multi
git checkout multi
2. 拉取最新的 multi 分支代码
确保 multi 分支是最新的，避免合并时出现冲突：

sh
git pull origin multi
3. 合并你的修改分支
将你的修改分支（如 test-auto-reconnect）合并到 multi 分支：

sh
git merge test-auto-reconnect
4. 解决冲突（如果有）
如果在合并过程中出现冲突，Git 会提示哪些文件存在冲突。你需要手动解决冲突：

打开冲突文件，找到冲突标记（<<<<<<<, =======, >>>>>>>），并根据需求保留或修改代码。

解决冲突后，标记文件为已解决：

sh
git add <冲突文件>
继续合并过程：

sh
git merge --continue
5. 测试合并后的代码
在合并完成后，确保代码功能正常。运行测试用例或手动测试关键功能。

6. 提交合并结果
如果一切正常，提交合并结果：

sh
git commit -m "Merge test-auto-reconnect into multi"
7. 推送到远程仓库
将合并后的 multi 分支推送到远程仓库：

sh
git push origin multi
